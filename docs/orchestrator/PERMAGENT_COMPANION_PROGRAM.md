# Permagent companion integration program

Status: planned execution; C0 evidence/ownership active. Created 2026-09-05.

## Product contract

Permagent is the operator's evolving companion. Its home is the app and OS;
it coordinates available computer tools under explicit capabilities and OS
permissions. Full app integration is not unrestricted authority. Data protection,
operator control and truthful uncertainty take precedence over task completion.
Persistence means learning from failure and proposing safe recovery, never
concealing failure or bypassing a permission boundary.

Recognition recall uses the existing Spectral library: context cues retrieve
attributed memories; corrections, contradiction, forgetting and privacy scope
must survive device changes. No parallel memory or trust database is permitted.
Do not send private memories or prompt bodies to new services to improve recall.

Prefer local inference when its measured capability, latency, context capacity
and hardware availability meet the job. An unavailable local model is not a
reason to silently transmit private data to cloud inference. Configured cloud
fallback remains subject to existing data policy and approved spend scope.

Earned autonomy is task/capability-specific, evidence-backed, explainable and
revocable by the operator. A reputation score is not permission, cannot
self-authorize more tools, and must distinguish insufficient evidence from
failure. Record success, correction, reversal and safety incidents with source
evidence in existing durable records. Keep operator trust private by default.
Digital-ID integration must first reuse an existing identity contract; no new
blockchain work or public reputation publication is authorized by this program.
MESH remains deferred.

Delight means responsive conversation, remembered relevant detail, clear
progress, accessible controls and recoverable actions. Do not add animation or
apparent confidence at the expense of readability, latency or truthfulness.

## Mandatory node packet and gates

Every implementation node declares dependencies, actual files allowed, relevant
Spectral/project brief, invariant, smallest proposed edit, regression test,
integration consumers, expected side effects, rollback, worker/model, budget,
timeout and escalation condition. Use existing frameworks and code patterns.
If the existing architecture cannot support a requirement, report the concrete
gap before introducing another mechanism.

Sequence: reproduce -> add regression -> surgical fix -> targeted verification
-> adjacent contract/UI integration -> independent review where risk warrants
-> retain receipt. No production code change without a new or extended
regression test. A backend-only patch does not complete a user-facing feature.

Use a maximum of two unsuccessful repair attempts per bounded node before
root diagnosis/replanning. Never rerun an unchanged failed command merely to
wait. Infrastructure failures are distinct from assertions and remain gate
debt. No continuous polling; use worker completion and runtime events.

Root plans and integrates. Lower-cost qualified workers implement in disjoint
scopes. Record actual provider/model used, not merely the requested route.
Escalation needs evidence that the cheaper worker cannot satisfy its contract.
Tests use deterministic fakes first; live paid trials require an explicit numeric
cap within authorized spend before starting. Do not invent a cap as consent.

## C7 release journeys

Validate the exact daemon, macOS app, iOS app and watchOS build identifiers,
protocol compatibility and rollback. Devices need coherent capabilities, not
identical UI: unsupported watch operations must hand off clearly and safely.

| Journey | Required evidence |
|---|---|
| Recognize, correct, recall | Relevant prior detail with provenance; correction beats stale recall; no cross-operator leakage; offline behavior explicit |
| Speak and interrupt | User transcript, reply timing/highlighting where supported, cancellation, background-noise recovery, no stuck listening; accessible controls |
| Delegate computer work | Consequences and route visible, approved capability scope, cancellation/restart, verified result shown on each supported device |
| Change model/device | Next-turn routing stable, active work identity preserved, local/cloud policy visible, reconnect does not fabricate success or zero cost |
| Browser/tool lifecycle | Closed page cannot continue owned audio; navigation and permission failures visible; external effect not repeated after reconnect |
| Learn trusted repetition | Operator can inspect, correct and revoke task-scoped trust; no self-awarded permission, forged completion or public disclosure |

Retain screenshots, structured traces, regression commands/results, build IDs,
privacy-safe latency/cost samples and explicit not-run cases. Publish no raw
private conversation in receipts. Missing device access blocks only its gate,
not unrelated safe preparation. No Excellent or release claim until inherited
qualification requirements and these journeys pass. Final release remains an
operator approval with concrete changes, consequences and rollback instructions.
