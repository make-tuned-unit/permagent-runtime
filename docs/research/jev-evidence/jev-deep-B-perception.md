### RomanSlack/jev-drone [MEASURED with caveats] https://github.com/RomanSlack/jev-drone
MIT, 103 stars, pushed 2026-09-17. MuJoCo Skydio X2, camera-only.
Layered loop: 500Hz geometric controller (zero Jev) / 50Hz safety reflex (code, ALWAYS overrides Jev) / 15Hz camera->symbolic scene via classical CV depth+segmentation (zero Jev) / ~2.5Hz Jev tactical judgment (advisory only).
State = 5 forward range sectors, height of blocker, whether its top edge is visible, target position. THREE questions per call:
- `maneuver` Choice: hold_course/gap_left/gap_right/climb/brake/reacquire
- `risk` Score: clear->about to hit
- `target_truly_lost` Noul
Scenes fingerprinted so unchanged situation reuses last judgment -> 65s flight ~110 calls (80 calls/65s, 0.11s median latency, 96k tokens in one run).
RESULT (single 65s run, NOT seed-matched): baseline (no Jev, greedy heuristic) reaches 17.7m and stalls at station 2 every time (can't express "fly over"); Jev-engaged clears full 77.5m course, target-in-view 82% vs 19%, time-in-reflex 9% vs 65-71%, 0 collisions both.
HONEST CAVEAT (repo's own words): on an earlier simpler arena, seed-matched 3-run comparison showed NO advantage (0/3 crossed, same as baseline) — "extra maneuvering cost target visibility." Claim is narrow: baseline structurally incapable of the maneuver, Jev supplies it; not "model makes drone better at everything."
KEY LESSON: Jev initially refused to ever pick `climb` — not a model failure, a STATE-DESIGN bug: 5 horizontal sectors contained zero vertical info. Adding top-edge height + visibility + climb ceiling moved climb from never-chosen to p=0.93. "The state has to contain the answer."
Also: one Choice was muddy (p=0.24) but the Noul on same state was clean (lost=0.12) — search behavior gated on the Noul not the Choice; "use the primitive that actually fits the question."
STEAL: hard veto layer in code that can refuse Jev's proposal if it fails a measured check (asymmetric trust — advisory only, never authoritative for safety).

### kxzk/typesafe-jev-drone-demo [DEMO-ONLY] https://github.com/kxzk/typesafe-jev-drone-demo

### khordoo/jev-reflex-autonomy-lab [DEMO-ONLY, live demo linked] https://github.com/khordoo/jev-reflex-autonomy-lab
12 stars, pushed 2026-09-20 (today-ish). Explicit System1/System2 architecture: "what happens when fast typed System1 reflexes can ask a slower System2 reasoning model for advice without giving up control?"
1-15 drones, each independently reflexed by Jev (System 1, fast typed action decisions for EVERY active drone every tick). When confidence < configurable threshold, an ASYNC System2 planner (OpenRouter/GLM-5.3) gives ONE-USE strategic guidance; Jev never pauses waiting for it — keeps steering with its own local judgment, and only "consumes" the S2 guidance if/when it arrives (marked purple in telemetry vs green = pure S1). S2 never flies directly — advisory only, same veto/authority split as jev-drone.
Confidence threshold is user-adjustable; local rule-based controller exists so app runs with zero credentials (dev mock), live mode is opt-in per session.
STEAL — the CLEANEST articulation of the reflex/deliberation split in the whole corpus: S1 never blocks on S2; S2's answer is stale-checked and only applied if still relevant; asynchronous one-shot advice injected into a continuously-running reflex loop, not synchronous consultation.

### fhshaik/typesafe-mario [DEMO-ONLY] https://github.com/fhshaik/typesafe-mario — 321 stars (most-starred repo found)
No screenshots — object-centric JSON: player(pos/velocity/grounded/jump phase/powerup), trajectory(airtime/distance since takeoff/committed gap crossing), hazard(up to 3 enemies w/ projected positions + contact timing + takeoff deadline), terrain(obstacle/gap geometry + reliability), reaction_timing(measured observation-to-action delay), recent_control(chosen action/duration/progress/outcome), episode(lives/clock/progress/stalls).
7 legal actions: noop/right/right_jump/right_run/right_run_jump/jump/left. Decision every 8 emulator frames.
THREE judgments per call: Choice(next macro), Noul(is a forward jump useful now), Score(immediate danger, for viz only).
Notably: "Exact timing arithmetic stays in code" — parser precomputes a `jump_must_start_this_decision` fact combining response age + enemy motion + cadence + jump-clearance time, and Jev just interprets that boolean-ish fact rather than doing the math itself — code does date/counting math, model does judgment. STEAL: precomputing a hard deadline fact ("must act NOW") in code and handing it to the model as a fact to weigh, rather than asking the model to compute timing itself.

### milanboers/jev-plays-pokemon [DEMO-ONLY, working] https://github.com/milanboers/jev-plays-pokemon — 3 stars
No vision. Explicit callout: "Jev has no conversation history... the harness itself does the remembering" — re-injects short-term memory into EVERY snapshot (up to 8 deduped recent dialog hints + last 12 high-level actions+outcomes, oldest->newest). This is the clearest statement in the corpus of Jev's fundamental statelessness and how apps compensate.
State per turn: instruction block (incl. Gen1 type chart + long-term goal), decoded screen text, walkability map, room map w/ `explored_fraction`, nearby objects w/ relative direction ("Mom: at C8, 2 tiles WEST, 3 tiles SOUTH"), goals, player/party/bag/battle/flags, recent_hints, recent_actions.

STEAL: "flattened goal sampling" — deliberately not always taking the argmax, to avoid the reflex layer hard-locking into a repeated bad decision loop. Directly relevant to an always-on background daemon that could get stuck repeating a typed judgment.

### zeredy879/minojev [MEASURED, rigorous — most important "shape of the model" repo] https://github.com/zeredy879/minojev — MIT, 25 stars
Repo's own badge: decision head is **~0.8M params** (brief said 547K — discrepancy noted), frozen backbone (Qwen3-1.7B). Reads calibrated typed distributions straight from hidden states in **one forward pass, decode_steps: 0** — zero output tokens, nothing to parse.
Method: cache each candidate's (state+question+option) hidden state from ONE forward pass, train only the ~0.8M-param "scorer + set attention" head on cached vectors with distribution losses, then fit one temperature per primitive on held-out outcomes. Trained in minutes on an Apple Silicon laptop.
MEASURED (120-decision suite, banking77/CLINC150/Amazon Polarity/GSM8K-verification, same backbone all 3 conditions): head-trained 95.8% acc / ECE 0.024 / 0 output tokens / p50 264ms / p95 ~0.6s; zero-shot logits readout (no training) 88.3% acc / 0 tokens; generative baseline (chat template, 1-letter answer) 80.0% acc / 3.48 output tokens / p50 361ms / p95 ~3.3s. Head-trained typed reader beats the SAME model's own generated answer by +15.8 points AND is ~5x faster p95 — purely from reading hidden states instead of decoding.
Full suite (200 req): 97.5% acc, ECE 0.014; at confidence>=0.9 covers 89.5% of requests at 98.9% accuracy — explicitly framed as usable for an accept/escalate policy.
HONEST OOD BOUNDARY: on domains never seen in training, head-trained model scored 31.7% vs generative baseline's 40.0% — head training SPECIALIZES and can be WORSE than doing nothing extra under domain shift.
STEAL: reading a calibrated typed answer directly off a frozen local model's hidden states turns ANY open-weight model already running into a Jev-shaped perception primitive at near-zero latency; the confidence>=0.9 coverage stat is a ready-made accept/escalate threshold.

### gaborishka/jev-canvas [DEMO-ONLY, most detailed voice spec in corpus] https://github.com/gaborishka/jev-canvas — MIT, 2 stars
Voice + pointing-finger (MediaPipe hand tracking) draws on a tldraw canvas. "Every transcript update, PARTIAL or final, produces one request to Jev" — i.e. re-judges on every partial, not just on final ASR output. THE EIGHT (actually nine incl. conditional) questions per request, verbatim from `shared/questions.js`:
1. `is_command` (Noul) — Is the speaker addressing the canvas at all?
2. `complete` (Noul) — Is the instruction finished, so it can be carried out now?
3. `action` (Choice) — create/move/delete/recolor/resize/duplicate/clear/undo/redo/none
4. `shape` (Choice) — 1 of 11 shape kinds, or none
5. `color` (Choice) — 1 of 13 tldraw colours, or none
6. `target` (Choice) — which existing shape the instruction is about, or none
7. `where` (Choice) — point/center/8 regions, or none
8. `size` (Score) — 0-4 rubric tiny->huge, 2 = nothing said
9. `text_span` (Choice, conditional) — which extracted span is the text to write (only present when transcript has candidate spans)
THRESHOLDS (all in `shared/policy.js`, i.e. all commit/rollback logic is plain code, not the model): `is_command >= 0.5` else ignored entirely; `action >= 0.55`; `complete >= 0.6`; a command needing a place WAITS for a 900ms pause unless place is already clear (`where >= 0.6`) — so "make a circle" doesn't fire mid-utterance before "...here" arrives. `target` below threshold falls back in order: shape under a spoken "this" -> only shape on page -> current selection.
PARTIAL-TRANSCRIPT COMMIT MECHANISM: pointing words are captured AT THE MOMENT SPOKEN, not when the model's answer returns — a 3s rolling trail of fingertip positions is kept and read back `SPEECH_LAG_MS` (300ms) earlier, because a word reaches the transcript after it was said. This is how "move this there" resolves two different points from one sentence. No explicit "rollback" of an already-committed partial judgment was found — instead the system re-runs on every partial and only ACTS once `complete>=0.6` and the specific field threshold is met, so early/wrong partials just get superseded by the next partial's judgment (the commit gate is downstream of the repeated judging, not a revocation of a prior action).
"Anything not addressed to the canvas is ignored — 'so anyway, what do you want for lunch' scores is_command ~2%." ~350ms per spoken word (from repo description).
STEAL: judging every ASR partial (not waiting for endpointing) while gating action ONLY on a separate `complete` Noul plus a debounce window for place-dependent commands — this is a concrete, working design for the "commit or roll back a partial-transcript decision" problem in the task brief.

### jyatesdotdev/jev-logtriage [DEMO-ONLY, clean reference architecture] https://github.com/jyatesdotdev/jev-logtriage — MIT, 1 star, PyPI package
"Prometheus is good at conditions you already know how to write in PromQL. This is for the rest." ONE call per log source/batch answers SIX questions (question IDs never sent to the model, only instructions — avoids leaking internal naming as a hint/shortcut):
- `is_routine_noise` (Noul) — would an on-call engineer dismiss this?
- `severity` (Score 0-3, routine->critical)
- `impact_scope` (Score 0-3, one pod->cluster-wide)
- `needs_action` (Noul) — should a human do something?
- `auto_remediable` (Noul) — is there a safe, unambiguous automated fix?
- `category` (Choice) — app_error/resource/infra/network/config/security/expected_noise
Named patterns (from TypeSafe's own docs, linked): "speculative fan-out" (ask all 6 up front, ignore answers that don't apply — same idea AkashPriyadarshii/jev-scout will use), "composite scoring" (`priority = 0.60*severity/3 + 0.40*impact/3`, weights live in code not the model), "confidence-gated routing".
GATES IN ORDER (all in code): (1) is_routine_noise>=0.80 AND severity<page-line -> suppress; (2) needs_action<0.50 -> watch; (3) min confidence < floor(0.50) -> review; (4) severity>=2.0 AND priority>=0.70 -> page; (5) auto_remediable>=0.85 AND safe category -> auto_remediate_candidate (a LABEL ONLY — "this repo does not restart pods, call webhooks, or page anyone"); (6) else -> notify. ### valentynkit/jev-belay [MEASURED, rigorous — the "honest_finish" idea, independently built and benchmarked] https://github.com/valentynkit/jev-belay — MIT, 17 stars
Explicitly diagnoses and fixes limpet's coin-flip failure above: "jev-belay establishes the facts first. Two regex belts read the transcript slice since your last prompt: one for a test/build/lint runner NAMED in a command, one for the runner's OWN SUMMARY in the output... If a check passed after the last change, the hook exits and Jev is never asked. Only when something changed and nothing proved it does the question go out, and the answer is read NEXT TO THAT EVIDENCE."
MEASURED on 100 labeled stops: **AUROC 0.976** for jev-belay's evidence-gated approach vs **0.777** for "judging the wording alone" (a direct, controlled ablation of the exact fix that mattered). At shipped threshold: blocks 8/100 turns, 7 rightly (87.5% precision). Only 17.7% of stops even reach the Jev question (477/2,694 in one real corpus) — the rest exit on cheap local regex/ledger checks alone, ZERO network cost. Median latency 346ms, cost $0.00005/checked-stop ($0.05 per 1,000).
Honest limit stated up front: "a turn with no file edits never reaches the question, so a read-only 'confirmed, tests pass' sails through" — the evidence gate that makes it accurate also creates its one blind spot.
STEAL: this is the single cleanest before/after ablation in the entire corpus proving that a fast typed judgment's reliability lives or dies on WHAT FACTS ARE IN THE STATE, not on the model itself — pairing Jev's semantic read with a cheap deterministic evidence extractor took the same underlying question from coin-flip to near-perfect.

### Nyarlathoteppppp/pi-heed [MEASURED, rigorous, largest benchmark in corpus, directly matches "runtime constraint checking from stated preferences"] https://github.com/Nyarlathoteppppp/pi-heed — MIT, 6 stars
Tracks CONVERSATIONAL POLICY as structured, versioned state across a whole session (not a keyword list): each constraint is `{id, sourceQuote, effect: DENY|ALLOW|REQUIRE_CONFIRMATION|REQUIRE_BEFORE, action, resource, scope: session|goal|run|once, exceptions, status: active|superseded|expired, provenance}`. Nested/scoped rules resolve most-specific-wins (file > dir > "tests" > "*"), NEWER instruction wins ties. "Nothing is deleted... after a reload or compaction the state replays to exactly what it was, WITHOUT CALLING JEV AGAIN" — i.e. the policy STATE persists as a deterministic data structure; Jev is only consulted to UPDATE it when new user language arrives, never to re-derive it from scratch.
Jev's job kept deliberately narrow (repo's own words): "It never writes a policy. For each message it classifies how each existing policy changed (KEEP/LIFT/NARROW/EXCEPTION/REPLACE/UNKNOWN), asks whether this is your go-ahead to start changing things, and answers a few signals... pi-heed applies only CONFIDENT answers, and takes resources from your message, never from Jev. Anything uncertain changes nothing."
MEASURED (79 scripted sessions, 261 labelled decisions, evolved across versions v0.3->v0.8): recall 71.4%->98.5%, false-block rate 5.2%->0.0%, lifecycle correctness 70.5%->100%, task success 61.2%->98.7%, cost/task $0.000051->$0.000058 (roughly flat despite huge accuracy gains — the improvement was architectural, not "ask more"). Sessions with >=1 false block: 16.3%->0.0%. A rules-only ablation (v0.8, no Jev) scored 90.9% recall / 1.0% false-block / 89.9% task success at $0 — Jev's marginal contribution over pure rules at v0.8 is ~+7.6pp recall and 89.9%->98.7% task success, for a small nonzero cost.
REAL-SESSION REPLAY (21 sessions, 594 messages, 9,090 real tool calls, replayed not executed): earlier version (v0.7.4) blocked 1,013 calls across 42 incidents; after a fix, v0.8.0 blocked only 95 calls across 16 incidents — almost all the earlier over-blocking was ONE PATTERN: "don't change anything yet, let's discuss" became a session-long ban that later casual go-aheads ("go ahead", "confirmed, start") didn't lift.
LIVE MODEL TEST (real pi sessions, two frontier-class models, rule stated then changed mid-session): pi-heed OFF, models broke a mid-session-changed rule 8/13 times; pi-heed ON, 0/13, with ZERO false blocks on the 30/30 unchanged-rule control runs. This is a rare RCT-style result: real models DO forget mid-session policy changes at a high rate (8/13 = 62%), and a typed constraint tracker catches essentially all of it.
STEAL: separating "durable structured policy state" (deterministic, replayable, free) from "does new language change the policy" (the one narrow thing Jev is asked) is the cleanest version of "typed perception updates a persistent world-model that code then enforces" in the whole corpus — directly the shape of a long-term memory graph + a fast perception layer that keeps it current.

### HyunjunJeon/jev-judgment [DEMO-ONLY] https://github.com/HyunjunJeon/jev-judgment — MIT, 3 stars
The Claude-Code/Codex-compatible sibling of pi-quiet-ask (same author-adjacent idea, different harness — an "Agent Skill" rather than a pi extension). Three call points: (1) before asking the user a closed question — if context already answers it, proceed and say so, else actually ask; (2) before a command that may destroy data/leak secrets/reach beyond task scope — stop and confirm if any dimension crosses threshold; (3) after a command fails — classify the failure and check output for secrets before retrying. Explicit non-negotiable escalation list, regardless of Jev's confidence: "Deletion outside the request, breaking changes, new dependencies, paid or remote actions, and anything the user said to ask about always go to the user" — i.e. a fixed allowlist of things Jev is never even asked to gate, only humans decide. Fails open with no key.
STEAL: the hard-coded "always ask a human" category list that sits ABOVE the typed-judgment layer entirely (not a threshold Jev can clear, a category Jev is never consulted on) — a clean pattern for Permagent's approvals inbox to guarantee certain action classes never get auto-approved no matter how confident the perception layer is.
