### How the HUD is Mounted

**Pure HTML overlay.** HUDs are React components rendered as **sibling divs** to the `<Canvas>` element in `WorldView.tsx`, using `position: absolute` and `zIndex: 20` (agent HUDs) or `zIndex: 10` (WorldHUD, AgentPicker). They are **not** CSS2DRenderer objects, not Three.js sprites, and not rendered inside the canvas.

```
WorldView.tsx JSX:
  <div style={{ position: 'relative', width: '100%', height: '100%' }}>
    <Canvas> ... </Canvas>                 // Three.js scene
    <WorldHUD ... />                       // z-index: 10, bottom-right
    <HenryHUD visible={...} onClose={...}/> // z-index: 20, top-left
    <LibrarianHUD visible={...} onClose={...}/>
    <AgentPicker ... />                    // z-index: 10, bottom-left
  </div>
```

## 3. DATA FLOW

### HenryHUD

**Endpoint:** `GET /api/henry/status`

**Response shape:**
```typescript
{
  identity: { name: string; traits: string[]; tone: string };
  current_state: 'idle' | 'in_conversation' | 'tool_call';
  active_sessions: { id: string; name: string; started_at: string }[];
  current_tool: string | null;       // "active" or null (issue #84: need tool NAME)
  tasks_in_flight: number;
  recent_tasks: { id: string; description: string; status: string; tool_used: string | null; completed_at: string | null }[];
  today_totals: { messages_sent: number; tasks_dispatched: number; scheduled_fires: number; memories_formed: number };
  lifetime_stats: { total_memories: number; total_sessions: number; days_active: number; first_active: string | null };
  next_scheduled: { id: string; cron: string; currently_running: boolean } | null;
}
```

**Mechanism:** `setInterval` polling at **1 second**, enabled only when `visible === true`. Cleanup cancels interval on unmount/hide.

**Backend data sources:** Persona (RwLock), session_manager, Spectral DB (rusqlite queries for tasks/messages), Brain memory.db (SQLite), scheduler job list.

### LibrarianHUD

**Endpoint:** `GET /api/librarian/status`

**Response shape:**
```typescript
{
  state: 'idle' | 'warming' | 'describing' | 'batch_complete' | 'error';
  current_task: string;
  current_memory: { key: string; content_preview: string } | null;
  schedule: { next_window_start: string | null; window_duration_min: number };
  session_stats: { batch_started_at: string | null; memories_described_this_session: number; avg_seconds_per_memory: number | null };
  lifetime_stats: { total_memories: number; described: number; pending: number };
  model: string;
  provider: string;
  error_message: string | null;
}
```

**Mechanism:** 1-second polling (same pattern as HenryHUD) **plus** WebSocket connection to `/events` for real-time token streaming during describe phase.

**WebSocket events consumed:**
- `LibrarianDescribeStarted` — resets token buffer
- `LibrarianDescribeToken` — appends token to streaming display
- `LibrarianDescribeRetry` — clears buffer, shows retry indicator
- `LibrarianDescribeCompleted` — marks quality (structured or fallback)

**Action endpoint:** `POST /api/librarian/run-now` (returns 409 if batch already running via BATCH_MUTEX)

### AgentPicker

**Endpoint:** `GET /api/agents` (falls back to hardcoded list if server unavailable)

### API Client

**File:** `src/lib/api.ts`

Custom `apiFetch<T>(endpoint, options?)` wrapper around `fetch()`. Auth via `x-secret-key` header (from `VITE_SECRET_KEY`) or Tauri IPC daemon token. Base URL: `VITE_DAEMON_URL` > `VITE_API_BASE_URL` > `http://127.0.0.1:3001` (Tauri) > `''`.

No axios, ky, or other HTTP library. Plain `fetch` + JSON parsing.

## 4. COMPONENT STRUCTURE

### HenryHUD

**Props:**
```typescript

  visible: boolean;
  onClose: () => void;
}
```

**Internal state:**
- `useState<HenryStatus | null>(null)` — full status from API

**Sections rendered (top to bottom):**

2. State pill: IDLE / IN CONVERSATION / TOOL CALL (color-coded)
3. Current tool: spinner + "processing..." when tool active
4. Active sessions: up to 3 sessions with relative timestamps

**One monolithic component.** No sub-components extracted.

## 7. GAPS / RISKS

### Adding a Tabbed HUD Structure

| Risk | Severity | Detail |
|------|----------|--------|
| Monolithic HUD components | Medium | HenryHUD and LibrarianHUD are single-file, single-component. All sections are inline JSX with inline styles. Extracting sections into tab panels requires carving out sub-components. |
| Inline styles everywhere | Medium | HUD components use inline `style={}` objects, not Tailwind. A tabbed structure needs consistent styling — either migrate to Tailwind or establish a shared style-object pattern for the tab bar. |
| No shared HUD chrome | Medium | Each HUD duplicates the header, close button, ESC handler, polling pattern, and state-pill rendering. A tabbed structure should extract a shared `AgentHUDShell` wrapper. |
| No existing tab primitive in world/ | Low | `BrowserTabs.tsx` exists but is Tailwind-styled and browser-specific. Would need a new tab component or adaptation. |
| `activeHud` is a union, not extensible | Low | Currently `'henry' \| 'librarian' \| null`. Adding more agents means widening this union. Consider switching to `string \| null`. |
| Only two agents have HUDs | Low | Aria, Felix, Nova are placeholder agents with no backend. Clicking them sets third-person camera but shows no HUD (`setActiveHud(null)`). |

### Adding On-Chain Reads

| Risk | Severity | Detail |
|------|----------|--------|
| No blockchain libraries | High | Zero EVM tooling installed. Need to add viem (or ethers) + a provider (public RPC or Alchemy/Infura). |
| No RPC URL config path | High | No mechanism for user-supplied RPC URLs. Would need a new env var (`VITE_RPC_URL`) or settings UI. |
| No wallet connection | High | No wagmi/RainbowKit/ConnectKit. If wallet signing is needed, full wallet stack required. |
| API client is REST-only | Low | `apiFetch` targets the local daemon. Chain reads would either go direct from frontend (viem) or through a new backend route. |
| CORS / CSP | Medium | Tauri app may need `allowlist` or CSP changes to reach external RPC endpoints. |

### General Tech Debt / In-Flight Work

| Item | Reference | Impact |
|------|-----------|--------|
| `current_tool` returns "active" not tool name | Issue #84 | HenryHUD can't display which tool is running |
| Henry trim color collision with global neonCyan | Issue #87 | `#00D9FF` used for both Henry's identity and the global accent; confusing when other agents are cyan-trimmed |
| No shared toast primitive | Issue #45 | Only `AutomateView` has a local `completionToast`. No global notification system. |
| Leveling / XP design not started | Issue #86 | Lifetime stats are substrate for future XP system but no design exists |
| BATCH_MUTEX test missing | Issue #36 | Librarian's concurrency guard has no integration test |
| `/api/agents` endpoint returns minimal data | — | No per-agent status, no capability list. Hardcoded fallback in `useAgentStates.ts` |
| Placeholder agents (Aria, Felix, Nova) | — | Rendered in scene with wander AI but have no backend identity, no HUD, no real functionality |
| ChatWidget deleted, ChatLauncher only | — | Chat opens in a separate Tauri window. No in-panel chat. Could complicate HUD-to-chat flows. |
| No test coverage for HUD components | — | Only one test file exists (`time-decay.test.ts`). No component tests. |
| WorldView state is local `useState` | — | Camera mode, selected agent, active HUD are all local to WorldView. Not in Zustand store. If other components need to know which agent is selected, this must be lifted. |

Two Tauri configs exist. The **desktop** app (`ui/desktop`) is the shipping product; the **command-center** config is a standalone dev harness.

### Command-center config (`ui/command-center/src-tauri/tauri.conf.json`, line 24)

```

img-src     'self' data:;
style-src   'self' 'unsafe-inline'
```

### Directive-by-directive analysis

| Directive | Desktop | Command-Center | Impact on new features |
|-----------|---------|----------------|----------------------|
| **`connect-src`** | `'self'` + localhost:3001 (HTTP+WS) + Google Fonts | `'self'` + localhost:3001 + 127.0.0.1:9844 | **Blocks all external HTTPS.** Any RPC call (Alchemy, Infura, public RPC, Arweave gateway) will be refused. Must add explicit origins. |
| **`img-src`** | `'self' data: blob:` + localhost:3001 | `'self' data:` | **Blocks external image URLs.** Loading avatars from `arweave.net` or any HTTPS host will fail. Must add `https://arweave.net` (and any gateway domains like `https://*.arweave.net`). |
| **`default-src`** | `'self'` | `'self'` | Fallback for any directive not explicitly listed. Blocks everything external by default. |
| **`script-src`** | `'self' 'unsafe-inline' 'unsafe-eval'` | Not set (falls back to `default-src 'self'`) | No impact on outbound calls. `unsafe-eval` is present in desktop only (likely for Vite HMR or Three.js shader compilation). |
| **`style-src`** | `'self' 'unsafe-inline'` + font CDNs | `'self' 'unsafe-inline'` | No impact on outbound calls. |
| **`font-src`** | `'self'` + font CDNs | Not set (falls back to `default-src 'self'`) | No impact. |
| **`frame-src`** | `'self' https: http:` | Not set | Permissive for iframes. No impact on fetch/XHR. |

### Dev vs Prod enforcement

| Mode | CSP enforced? | Detail |
|------|--------------|--------|
| **Dev** (`npm run dev`) | **No** | Tauri's `devUrl` points to `http://localhost:5273` (Vite dev server). In dev mode with a `devUrl`, Tauri **does not inject the CSP meta tag** — the webview loads from the dev server directly, bypassing CSP. Outbound fetches to any origin work freely in dev. |
| **Prod** (built `.app`) | **Yes** | Tauri serves assets from the `frontendDist` bundle via its custom `tauri://` protocol and injects the CSP as a `<meta>` tag into every HTML page. All directives are enforced by the webview. |

No `dangerousDisableAssetCspModification` flag is set. No per-capability CSP overrides exist in `capabilities/default.json`.

### Required CSP changes for on-chain reads + Arweave avatars

**`connect-src` additions needed:**

| Origin | Reason |
|--------|--------|
| `https://*.alchemy.com` or `https://*.infura.io` | EVM JSON-RPC (if using hosted provider) |
| `https://arweave.net` | Arweave gateway (if reading tx data directly) |
| `https://*.arweave.net` | Arweave subdomains (some gateways use `*.arweave.net`) |
| Any public RPC URL | If using a public endpoint like `https://eth.llamarpc.com` |

**`img-src` additions needed:**

| Origin | Reason |
|--------|--------|
| `https://arweave.net` | Avatar images served from Arweave gateway |
| `https://*.arweave.net` | Arweave subdomain gateways |
| `https:` | If avatars could come from arbitrary HTTPS hosts (broader but simpler) |

**Both configs must be updated** — desktop (shipping app) and command-center (standalone dev). The desktop config is the one that matters for production.
