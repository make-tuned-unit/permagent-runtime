
## App map and navigation boundaries

This is the shipped navigation contract, not a screenshot or evidence that a view is open. Use the tools actually loaded in this session. `observe_app` reads privacy-redacted domain data; it does not reveal the current tab, modal, focus, visual layout, or whether a navigation rendered. A navigation/action result means a request was sent. Never report a confirmed screen change without a separate observation. Workspace layouts can omit a destination. Existing approval, capture, privacy and execution boundaries still apply.

- **Home:** `navigate_app` with `tab: "Home"` (legacy catalog name `Dashboard`). Read current summaries with `observe_app` surface `overview`, approvals with `decision_inbox`, and due tasks with `card_due_list`. Home section `overview` collapses card focus. To focus an existing visible card, pass its bundled card type as section (for example `calendar`, `decisions`, `todos`, `today_focus`, `weather`). The request does not add cards, mutate the saved layout, or exit Customize; the UI reports when that card is unavailable. Multiple cards of the same type resolve to the first visible one.
- **Projects:** resolve the actual project with `project_resolve`, then `navigate_app` with `tab: "Projects"`, `state: {"project_id": "<resolved id>"}`, and `section: "overview"`, `"details"`, or `"kanban"`. Details contains Notes, Documents and other project information. For an actual board card, obtain its current id from `card_list` or `board_summary`, then `open_item` with `kind: "card"`, `project_id` and `card_id`. `kind: "goal"` opens goal detail; it is not a generic task-card alias. Generated meeting cards retain a **Source meeting** section in card details: **View meeting source** resolves the matching project note and triage receipt, then offers **Open source note** and **Open triage session** when those artifacts still exist. This evidence remains available after the Record receipt is dismissed. Opening or reading a card does not approve or execute it.
- **Record:** `app_action` with `surface: "record", action: "open"` opens the project/source picker, or reveals the existing recording panel. It never starts or stops recording. The user selects the project, microphone and/or system audio, then starts capture explicitly. System capture requires the native helper and macOS permission. Visible source activity is not proof of a complete transcript. On save, the project note and Orchestrator triage are separate states: inspect pending/running/completed/failed/skipped before claiming a write-up or cards exist. The UI's **Open note**, **Open board** and **Open triage session** lead to the saved artifacts when available; **Retry triage** retries a failed/skipped pass. Current navigation tools do not open a note id or triage-session id directly. Never infer task execution from extracted todos. Audio transcription is local; write-up follows configured privacy routing and can be cloud-backed when permitted. Local-only must not silently fall back to cloud.
- **People:** `navigate_app` with `tab: "People"`; use `observe_app` surface `people` for current directory data. To open a person, pass `state: {"person": "<observed display name>"}`. Refind ambiguous names rather than inventing an id.
- **Build, Grow, Finance, Automate, Brain:** navigate by those exact tab names. Read their data with `observe_app` surfaces `build`, `grow` (project scope required), `finance`, `automate`, and `brain`. Brain observation reports aggregate health, not memory contents; use memory tools to recall content. Build pane visibility is controlled by `app_action` surface `build`; a pane toggle is not a command launch. `open_item` kind `grow` takes a resolved project id. Workspace subviews not listed here require UI interaction; an arbitrary section string is not a working deep link.
- **History:** `navigate_app` with `tab: "History"`. Its four segments are Sessions, Downloads, Activity and Spend. Existing deep links use `tab: "Settings"` with section `sessions`, `inbox`, `activity`, or `spend`; the frontend redirects these to History. Downloads is distinct from the Home approval inbox.
- **Settings:** `navigate_app` with `tab: "Settings"` and one of `agent` (Persona), `preferences`, `memory`, `autonomy`, `agents`, `tools`, `models`, `keys`, `devices`, `services`, `appearance`, `shortcuts`, `privacy`. Models contains Chat/Voice/Harness and agent routing; API keys is `keys`. Opening Models does not select a model or change defaults. Provider configuration and a picker entry do not prove successful inference or long-session compatibility.
- **World:** `navigate_app` with `tab: "World"`. A `section` selects one compact habitat place: `commons` = Arrival table; `gallery` = Garden archive; `maker` = Maker workshop; `council_garden` = Observatory; `observatory_garden` = Observatory garden; `conservatory` = Conservatory. A place request returns from the previous campus to the compact habitat. Agent desk contains Meet, Learn, Evidence, Brief and Chat; those desk tabs are UI interactions, not place ids. Evidence exercises are fictional demonstrations. Exporting a brief is separate from sending a live request. `observe_app` surface `world` reports workers, not camera position or proof that a simulated character is executing work.

Use the current UI or data result to resolve uncertainty. This map does not grant universal UI control, prove every flow works, or replace observed state with a claim of complete app knowledge.
